# Torrent Audio для Lampa — 0.1.6

Экспериментальный плагин аудиодорожек TorrServer/GStreamer для встроенного плеера Lampa, включая запуск через MediaStationX на Samsung.

## Установка

Опубликуйте torrent-audio.js в своём GitHub Pages. В Lampa замените прежнюю запись расширения адресом `https://lod255.github.io/lampa_plugins/torrent-audio.js?v=0.1.6`, затем полностью перезапустите MediaStationX. Не оставляйте две активные копии плагина.

При запуске фильма прямой поток не меняется. Плагин запрашивает `/gst/{hash}/probe?index=N` и показывает аудиодорожки в штатном меню. Номер audio берётся из Tracks[].Index.

При выборе дорожки сначала проверяется master.m3u8. При ошибке HTTP/CORS/таймауте переключение не выполняется. Подготовка HLS на сервере при этом может влиять на ранее открытый HLS той же задачи. Затем используется штатный механизм смены серии `PlayerPlaylist.listener.send('select', ...)`: Lampa полностью очищает плеер и запускает поток через свою внутреннюю функцию play. Плейлист и обработчик возврата сохраняются. Это заменяет прямые вызовы PlayerVideo.destroy/url прежних версий. Поведение рекламы определяется штатной логикой Lampa; отсутствие повторной рекламы не гарантируется.

После появления метаданных восстанавливается позиция. Для играющего видео таймер проверки снимается только после реального продвижения currentTime. Для паузы восстанавливается пауза. Через 60 секунд без восстановления плагин пытается полностью перезапустить прежний URL. При повторном сбое предлагает открыть фильм заново. Пользовательское закрытие плеера отменяет переход и таймер.

## Сервер

Адрес по умолчанию `http://192.168.1.2:8090`. Для изменения в консоли после загрузки Lampa:

```javascript
LampaTorrentAudio.setGateway('http://АДРЕС:ПОРТ');
```

Настройка сохраняется в Storage. Отдельного пункта интерфейса нет. Прямые ссылки /stream с 40-символьным хэшем link преобразуются только для того же имени сервера, что указано в настройке. Шлюз должен обслуживать этот TorrServer. Готовые ссылки /gst/{hash}/master.m3u8 используют свой исходный сервер.

Сервер должен разрешать CORS со страницы Lampa; HTTP при HTTPS также может блокироваться браузером. Нужны рабочие /probe, HLS-манифесты, init и сегменты. Проверка HTTP 200 манифеста не доказывает, что декодер телевизора воспроизводит сегменты.

## Совместимость и проверка

Нужны PlayerPlaylist.listener/get/set, Player.listener, PlayerPanel.setTracks и PlayerVideo.video/play/pause. Механизм перезапуска проверен по открытым исходникам yumata/lampa-source. Проверена модель событий destroy/start, сохранение таймера, подготовка HLS до остановки, восстановление позиции, сохранение плейлиста, откат при таймауте и отмена при закрытии. Регрессия: принятый seek без воспроизведения больше не отключает таймер.

На Samsung/MediaStationX новая версия ещё не проверена. Полное переключение не гарантирует устранения серверных ошибок, несовместимости кодеков или недоступности сегментов.

Для удаления отключите расширение и перезапустите Lampa. `LampaTorrentAudio.destroy()` снимает обработчики, отменяет таймеры и восстанавливает метод панели. `LampaTorrentAudio.getLastError()` возвращает последнее синхронное исключение. `LampaTorrentAudio.refresh()` перечитывает дорожки, когда переключение не выполняется.

Исходники: https://github.com/yumata/lampa-source/blob/main/src/interaction/player.js и https://github.com/yumata/lampa-source/blob/main/src/interaction/player/playlist.js

## Диагностика 0.1.5

Сообщение таймаута содержит состояние до отката: phase, t (текущая/целевая позиция), d (длительность), ready (readyState), net (networkState), err (MediaError.code), pause, seek, resume. getStatus() показывает текущее состояние, getLastStatus() — последний снимок таймаута. Адреса и названия файлов не включаются. Это диагностика, а не подтверждённое исправление воспроизведения на Samsung.

## Исправление 0.1.6

Восстановление больше не ждёт seeking=false перед play(). При позиции в пределах двух секунд от целевой повторная перемотка не выполняется. В остальных случаях currentTime устанавливается один раз, затем вызывается play(), а таймер остаётся до фактического продвижения дальше целевой позиции. Проверены модели readyState=4 и seeking=true, близкая/далёкая позиция, отсутствие повторных seek и сохранение паузы. Проверка на телевизоре остаётся необходимой.
