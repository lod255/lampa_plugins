# Плагины для Lampa

Два независимых плагина для Lampa. Можно подключить один или оба.

| Файл | Версия | Назначение |
| --- | --- | --- |
| [torrent-style.js](torrent-style.js) | 1.0.1 | Цветные плашки характеристик раздач |
| [torrent-audio.js](torrent-audio.js) | 0.1.10 | Выбор аудиодорожек через TorrServer/GStreamer HLS; экспериментальный |

## Установка через GitHub Pages

1. Загрузите нужные JS-файлы в публикуемую папку репозитория GitHub Pages.
2. Дождитесь публикации. Проверьте, что адрес файла открывает JavaScript, а не HTML или ошибку 404.
3. В Lampa откройте настройки расширений и добавьте адрес нужного плагина:

```text
https://lod255.github.io/lampa_plugins/torrent-style.js?v=1.0.1
https://lod255.github.io/lampa_plugins/torrent-audio.js?v=0.1.10
```

4. Отключите другие плагины оформления торрентов, если устанавливаете torrent-style.js.
5. Перезапустите Lampa. На Samsung при запуске через MediaStationX полностью закройте и заново откройте MediaStationX.

Для обновления замените файл на GitHub Pages и параметр версии в существующей записи расширения. Не оставляйте две активные копии одного плагина. Для удаления отключите расширение и перезапустите приложение.

## Оформление торрентов — torrent-style.js

Самостоятельный плагин без привязки к ByLampa, внешних библиотек и сетевых запросов. Исходные названия, ссылки и значения раздач не изменяются.

### Цветовая градация

| Показатель | Цвета |
| --- | --- |
| Сиды | Меньше 5 — красный; 5–19 — янтарный; от 20 — зелёный |
| Скачивающие | Голубой |
| Битрейт | Меньше 20 — голубой; 20–<50 — янтарный; от 50 Мбит/с — красный |
| Размер | Меньше 5 — зелёный; 5–<10 — голубой; 10–<25 — янтарный; от 25 ГБ — красный |
| Разрешение | SD — красный; HD — янтарный; FHD — зелёный; 2K — голубой; 4K/8K — фиолетовый |

Разрешение оформляется в существующей плашке `.m-resolution`. Если её нет, но в названии раздачи явно указано разрешение, плагин добавляет плашку в строку деталей. HDR сам по себе не считается разрешением 4K. Неизвестные значения остаются без окраски.

Пороги доступны в объекте `config` в начале JS-файла. Настройки не добавляются в меню Lampa. Цвет не является оценкой качества видео или гарантией скорости просмотра.

### Обновление и удаление оформления

Для обновления замените JS-файл в репозитории и дождитесь публикации. Если клиент использует старую копию, замените адрес расширения на тот же адрес с новым параметром, например `torrent-style.js?v=2`, и перезапустите клиент. Не добавляйте вторую активную копию расширения.

Для удаления отключите или удалите расширение и перезапустите Lampa. Для диагностики из консоли доступны `LampaTorrentStyle.version`, `LampaTorrentStyle.refresh()` и `LampaTorrentStyle.destroy()`.

### Проверка оформления на устройстве

Проверьте открытие списка торрентов, сортировку, фильтры, подгрузку результатов и повторный вход в список. Убедитесь, что длинные названия и раздачи без битрейта отображаются корректно, а управление пультом сохранилось.

Плагин рассчитан на разметку `.torrent-item` и её поля `__seeds`, `__grabs`, `__bitrate`, `__size`, `__title`, `__details`, `__ffprobe`. Работа на текущей версии lampa.mx и конкретном телевизоре требует проверки после установки. Для устаревших браузеров без MutationObserver автоматическое оформление новых результатов не поддерживается.

## Аудиодорожки — torrent-audio.js

Экспериментальный плагин для встроенного плеера Lampa и TorrServer с GStreamer, в том числе для Samsung через MediaStationX. В версии 0.1.9 пользователь подтвердил переключение дорожек с сохранением позиции и включение субтитров на Samsung UE43NU7170UXRU через MediaStationX. В 0.1.10 убраны уведомления об обычной подготовке и запуске дорожки.

При запуске фильма прямой поток не меняется. Плагин запрашивает `/gst/{hash}/probe?index=N` и показывает аудиодорожки в штатном меню. Номер audio берётся из Tracks[].Index.

При выборе дорожки сначала проверяется master.m3u8. При ошибке HTTP/CORS/таймауте переключение не выполняется. Подготовка HLS на сервере при этом может влиять на ранее открытый HLS той же задачи. Затем используется штатный механизм смены серии `PlayerPlaylist.listener.send('select', ...)`: Lampa полностью очищает плеер и запускает поток через свою внутреннюю функцию play. Плейлист и обработчик возврата сохраняются. Это заменяет прямые вызовы PlayerVideo.destroy/url прежних версий. Поведение рекламы определяется штатной логикой Lampa; отсутствие повторной рекламы не гарантируется.

После появления метаданных восстанавливается позиция. Для играющего видео таймер проверки снимается только после реального продвижения currentTime. Для паузы восстанавливается пауза. Через 60 секунд без восстановления плагин пытается полностью перезапустить прежний URL. При повторном сбое предлагает открыть фильм заново. Пользовательское закрытие плеера отменяет переход и таймер.

### Настройка сервера

Адрес по умолчанию `http://192.168.1.2:8090`. Для изменения в консоли после загрузки Lampa:

```javascript
LampaTorrentAudio.setGateway('http://АДРЕС:ПОРТ');
```

Настройка сохраняется в Storage. Отдельного пункта интерфейса нет. Прямые ссылки /stream с 40-символьным хэшем link преобразуются только для того же имени сервера, что указано в настройке. Шлюз должен обслуживать этот TorrServer. Готовые ссылки /gst/{hash}/master.m3u8 используют свой исходный сервер.

Сервер должен разрешать CORS со страницы Lampa; HTTP при HTTPS также может блокироваться браузером. Нужны рабочие /probe, HLS-манифесты, init и сегменты. Проверка HTTP 200 манифеста не доказывает, что декодер телевизора воспроизводит сегменты.

### Совместимость и проверка аудиодорожек

Нужны PlayerPlaylist.listener/get/set, Player.listener, PlayerPanel.setTracks и PlayerVideo.video/play/pause. Механизм перезапуска проверен по открытым исходникам yumata/lampa-source. Проверена модель событий destroy/start, сохранение таймера, подготовка HLS до остановки, восстановление позиции, сохранение плейлиста, откат при таймауте и отмена при закрытии. Регрессия: принятый seek без воспроизведения больше не отключает таймер.

Работа версии 0.1.9 подтверждена пользователем на Samsung UE43NU7170UXRU через MediaStationX. Полное переключение не гарантирует устранения серверных ошибок, несовместимости кодеков или недоступности сегментов.

Для удаления отключите расширение и перезапустите Lampa. `LampaTorrentAudio.destroy()` снимает обработчики, отменяет таймеры и восстанавливает метод панели. `LampaTorrentAudio.getLastError()` возвращает последнее синхронное исключение. `LampaTorrentAudio.refresh()` перечитывает дорожки, когда переключение не выполняется.

Исходники API Lampa: [player.js](https://github.com/yumata/lampa-source/blob/main/src/interaction/player.js), [playlist.js](https://github.com/yumata/lampa-source/blob/main/src/interaction/player/playlist.js).

### Диагностика

Сообщение таймаута содержит состояние до отката: phase, t (текущая/целевая позиция), d (длительность), ready (readyState), net (networkState), err (MediaError.code), pause, seek, resume. getStatus() показывает текущее состояние, getLastStatus() — последний снимок таймаута. Адреса и названия файлов не включаются. Это диагностика, а не подтверждённое исправление воспроизведения на Samsung.

### Изменения версии 0.1.6

Восстановление больше не ждёт seeking=false перед play(). При позиции в пределах двух секунд от целевой повторная перемотка не выполняется. В остальных случаях currentTime устанавливается один раз, затем вызывается play(), а таймер остаётся до фактического продвижения дальше целевой позиции. Проверены модели readyState=4 и seeking=true, близкая/далёкая позиция, отсутствие повторных seek и сохранение паузы. Проверка на телевизоре остаётся необходимой.

### Изменения версии 0.1.7

Если после первого play() время не продвигается, выполняются до трёх повторных вызовов с интервалом не менее 3 секунд. Продвижение времени откладывает повтор; подтверждённое восстановление, закрытие плеера или уничтожение плагина отменяет дальнейшие попытки. Повторная перемотка при этих попытках не выполняется. Сохранение паузы и общий таймаут отката 60 секунд остаются прежними.

Диагностика дополнена plays (число вызовов play) и play (calling/returned/resolved/rejected/threw/none). returned означает только возврат из метода Lampa, а не успешное воспроизведение. Если метод возвращает Promise, отслеживается его результат; перехваченные исключения и отклонения доступны через getLastError(). getLastStatus() сохраняет эти поля при таймауте перед откатом. Проверка на Samsung/MediaStationX остаётся необходимой.

### Изменения версии 0.1.8

При явном переключении дорожки на Samsung (Platform tizen или User-Agent tizen/samsung) плагин проверяет наличие HTML-видеоэлемента и Hls.isSupported(). При поддержке передаёт штатному плееру Lampa параметр hls_type=hlsjs для нового потока. Используется библиотека Hls, уже загруженная Lampa; дополнительные скрипты не скачиваются. Глобальные настройки не меняются, начальный прямой поток не перезапускается. Если библиотека, MSE или HTML-видеоэлемент недоступны, показывается уведомление и сохраняется обычный запуск.

Диагностика hls=js-requested означает запрос программного HLS через API Lampa, а не доказательство фактического выбора движка или успешного воспроизведения. auto означает отсутствие переопределения для других устройств; auto-unsupported и auto-nonvideo объясняют отказ от переопределения на Samsung. rollback означает восстановление прежних данных воспроизведения без повторного выбора движка. При успешном переключении getStatus() сохраняет выбранную метку для текущего сеанса. Для работы нужен плеер Lampa, поддерживающий параметр hls_type. Совместимость и воспроизведение на телевизоре требуют проверки.

### Изменения версии 0.1.9

Исправлен немедленный откат при восстанавливаемых событиях hls.js: error с явным fatal=false сохраняется в диагностике, но не прерывает переход. При этом настоящий MediaError с ненулевым кодом остаётся причиной отката. События с fatal=true или без признака fatal по-прежнему приводят к откату. Таймаут 60 секунд остаётся ограничением для восстановления.

При ошибке перед откатом сохраняется getLastStatus(), а уведомление включает состояние и cause — очищенную от HTTP(S)-адресов причину, полученную от Lampa. getStatus()/getLastStatus() дополнены streamError и streamFatal; getLastError() содержит последнюю причину с этапом stream. Причина в уведомлении ограничена 180 символами, в getLastError() — 400. Текст Lampa может содержать только details и fatal, без внутренней причины hls.js. Проверка на Samsung/MediaStationX остаётся необходимой.

### Изменения версии 0.1.10

Убраны всплывающие уведомления о подготовке дорожки и пробном запуске через hls.js. Предупреждения о недоступности hls.js, сообщения об ошибках и диагностические методы сохранены. Логика воспроизведения не менялась.
